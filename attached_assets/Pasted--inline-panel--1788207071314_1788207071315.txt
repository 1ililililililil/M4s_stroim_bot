Новая inline-панель управления фактически не работает.

После команды /panel бот по-прежнему отправляет старую текстовую панель со списком:

/settings
/stats
/remember
/knowledge

Поэтому не доверяй предыдущему отчёту о том, что inline-панель уже работает.

Проверь текущий код и исправь только проблему с открытием новой панели.

Нужно:

1. Найти ВСЕ обработчики команды /panel во всём проекте.
2. Проверить, нет ли старого handler в admin.py, panel.py или других файлах.
3. Убедиться, что существует только один активный обработчик Command("panel"), который открывает новую inline keyboard панель.
4. Проверить порядок регистрации router в app/main.py.
5. Убедиться, что router с новой панелью действительно подключён к Dispatcher.
6. Удалить или отключить только старый конфликтующий обработчик /panel, не ломая остальные старые команды.
7. Проверить, что /panel отправляет сообщение с InlineKeyboardMarkup и кнопками, а не обычный текстовый список команд.
8. Сохранить PostgreSQL/SQLite совместимость.
9. Не менять FAST → SMART → AI → FALLBACK маршрутизацию.
10. Не менять OpenRouter, модель, max_tokens=8192, очередь комментариев, idempotency и существующую логику обработки комментариев.
11. Не менять Secrets.

После исправления:

- запусти python -m compileall -q app tests
- запусти python -m pytest -q
- перезапусти только существующий workflow Start application
- проверь /health
- проверь Telegram polling
- проверь запуск comment processing queue

Главная обязательная проверка:

После отправки /panel бот должен показать новую кнопку-интерфейсную панель примерно с разделами:

🤖 Автоответы
📊 Статистика
🧠 База знаний
❓ Неотвеченные
💡 Кандидаты
⚙️ Настройки
🔄 Обновить
❌ Закрыть

Новая панель должна быть InlineKeyboardMarkup с нажимаемыми кнопками.

Не ограничивайся проверкой тестов — фактически проверь зарегистрированный handler и убедись, что старый текстовый ответ /panel больше не отправляется.
