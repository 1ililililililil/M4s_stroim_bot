Проведи диагностику и минимальную оптимизацию производительности существующего MCHS AI Admin Bot V3.

ПРОБЛЕМЫ:

1. Бот медленно обрабатывает Telegram-команды.
2. Бот долго анализирует комментарии.
3. Некоторые комментарии анализируются, но бот не отвечает на них.
4. Нужно понять, на каком этапе теряется или задерживается комментарий.

ВАЖНО:

Сначала проанализируй текущий код и логи.
Не переписывай проект с нуля.
Не меняй Telegram API, PostgreSQL, AI-провайдера или бизнес-логику без подтверждённой причины.

================================
1. ДОБАВЬ ИЗМЕРЕНИЕ ВРЕМЕНИ
================================

Добавь информативные логи времени выполнения для этапов:

- получение Telegram update;
- начало handler;
- проверка на дубликат;
- проверка SPAM;
- начало AI-анализа;
- окончание AI-анализа;
- генерация ответа;
- запись в PostgreSQL;
- отправка ответа в Telegram;
- полное время обработки комментария;
- полное время обработки команды.

Логи должны показывать длительность каждого этапа.

Не выводить API keys и Secrets.

================================
2. ПРОВЕРЬ БЛОКИРОВКИ ASYNCIO
================================

Проверь весь путь обработки Telegram updates.

Найди потенциальные блокирующие операции:

- synchronous requests;
- requests library внутри async handlers;
- time.sleep;
- синхронные PostgreSQL операции;
- тяжёлые AI-запросы;
- последовательное ожидание независимых операций.

Если найдены подтверждённые блокировки:

исправь их минимально, используя текущую async архитектуру.

Не создавать бесконечное количество фоновых задач.

================================
3. AI ОБРАБОТКА
================================

Проверь:

- какая модель OpenRouter используется;
- сколько времени занимает реальный AI-запрос;
- timeout;
- retry logic;
- не выполняется ли несколько AI-запросов для одного комментария;
- не анализируется ли один комментарий повторно.

Для одного комментария желательно делать минимальное количество AI-запросов.

Если сейчас анализ и генерация ответа выполняются отдельными запросами, рассмотри возможность объединить их в один запрос:

AI должен вернуть структурированный результат:

{
  "needs_reply": true/false,
  "reason": "...",
  "reply": "..."
}

Если комментарий не требует ответа, reply должен быть пустым.

Это позволит уменьшить количество AI-запросов.

================================
4. ПРОБЛЕМА "АНАЛИЗИРУЕТ, НО НЕ ОТВЕЧАЕТ"
================================

Проследи полный путь комментария:

Telegram update
→ handler
→ AI analysis
→ needs_reply decision
→ confidence/threshold check
→ auto_reply setting
→ database status
→ send_message/send_reply

Для каждого комментария логируй причину, если ответ НЕ был опубликован.

Например:

SKIPPED: auto replies disabled
SKIPPED: confidence below threshold
SKIPPED: needs_reply=false
SKIPPED: already processed
SKIPPED: spam
ERROR: Telegram send failed

Нужно, чтобы было точно понятно, почему бот проигнорировал комментарий.

================================
5. КОМАНДЫ БОТА
================================

Проверь handlers команд:

/start
/panel
/settings
/auto_on
/auto_off
/stats

Команды не должны ждать AI-анализ или обработку комментариев.

Если обработка комментария блокирует обработку команд:

сделай обработку тяжёлого AI-анализa неблокирующей для остальных Telegram updates, используя безопасную ограниченную фоновую очередь/задачу.

ВАЖНО:
сохранить порядок обработки одного и того же комментария и защиту от дублей.

================================
6. TELEGRAM ОТВЕТ
================================

Проверь, что ответ отправляется именно ответом на исходный комментарий.

Проверь корректность:

chat_id
message_id
reply_to_message_id

Если Telegram API возвращает ошибку:

логировать полный тип и текст ошибки, без Secrets.

================================
7. ПРОВЕРКА
================================

После диагностики:

1. Выполнить:
python -m pytest -q

2. Запустить:
python -m app.main

3. Выполнить реальные smoke tests:

- /start;
- /panel;
- один комментарий, требующий ответа;
- один обычный комментарий;
- один SPAM.

4. Замерить время каждого этапа.

================================
8. ЦЕЛЬ
================================

После оптимизации:

- команды должны обрабатываться быстро и не ждать AI;
- комментарии должны обрабатываться без блокировки polling;
- для каждого проигнорированного комментария должна быть точная причина;
- комментарий, который требует ответа и проходит текущий порог, должен автоматически получить один ответ;
- не должно быть двойных ответов.

================================
9. В КОНЦЕ ПОКАЖИ ОТЧЁТ
================================

Покажи:

1. Какие именно причины замедления были найдены.
2. Какие файлы были изменены.
3. Что было исправлено.
4. Среднее время:
   - обработки команды;
   - AI-анализа;
   - полной обработки комментария.
5. Для каждого тестового комментария:
   - отвечен / проигнорирован;
   - точная причина.
6. Статус:

Telegram polling: OK/ERROR
Commands: OK/ERROR
AI performance: OK/ERROR
Auto reply: OK/ERROR
Database: OK/ERROR
Duplicate protection: OK/ERROR
Healthcheck: OK/ERROR
Tests: OK/ERROR

Если возникнет новая техническая ошибка, остановись на первой ошибке и покажи полный лог.
