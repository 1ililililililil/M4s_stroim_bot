Добавь в MCHS AI Admin Bot V3 интеллектуальную память канала и поиск по базе знаний предыдущих публикаций.

Цель:

Бот должен отвечать на комментарии не только на основе:

- текущего комментария;
- текущего поста;
- родительского комментария;

но также использовать знания из предыдущих публикаций канала и сохранённой базы знаний.

Примеры:

Пользователь:
«Вы уже рассказывали про это?»

Бот должен иметь возможность найти предыдущую публикацию по теме.

Пользователь:
«А чем этот самолёт отличается от того, о котором вы писали раньше?»

Бот должен попытаться найти релевантную предыдущую публикацию и использовать её контекст.

Пользователь:
«А какие ещё способы тушения пожаров вы показывали?»

Бот должен искать по сохранённым знаниям канала.

==================================================
1. БАЗА ЗНАНИЙ КАНАЛА
==================================================

Используй существующую систему knowledge, если она уже есть.

Если текущая таблица предназначена для ручных записей /remember, расширь использование существующей архитектуры минимально.

Каждая запись знания должна по возможности содержать:

- id;
- chat_id;
- source_type;
- source_message_id;
- title или краткую тему;
- content;
- created_at.

source_type может быть логически:

post
manual
comment_context

Не создавай сложную новую архитектуру без необходимости.

==================================================
2. СОХРАНЕНИЕ ПУБЛИКАЦИЙ В ПАМЯТЬ
==================================================

Когда бот получает доступ к исходному посту комментария:

сохраняй информацию о публикации в базе знаний.

Но не создавай одинаковые записи повторно.

Используй уникальность:

(chat_id, source_message_id)

для публикаций.

Если публикация уже существует:

- не создавать новую запись;
- при необходимости обновить контент.

Сохранять нужно:

- текст поста;
- caption;
- структурированный post context;
- краткую тему, если она может быть определена без дополнительного дорогого AI-запроса.

Не вызывай отдельный AI-анализ только ради сохранения каждого поста.

==================================================
3. ПОИСК ПО ПАМЯТИ
==================================================

Добавь функцию логически такого назначения:

search_relevant_knowledge(
    query,
    chat_id,
    current_post_id=None,
    limit=3
)

Поиск должен:

- искать только знания текущего канала;
- отдавать наиболее релевантные записи;
- не возвращать текущий пост повторно, если это не требуется;
- ограничивать количество результатов;
- быть устойчивым к пустому результату.

Для первой версии не требуется vector database.

Используй существующую PostgreSQL/SQLite архитектуру.

Допустимый простой подход:

- поиск по ключевым словам;
- нормализация текста;
- поиск совпадений;
- ranking по количеству совпадений.

Если PostgreSQL уже используется в production и SQLite в тестах, решение должно работать в обоих окружениях.

Не добавляй внешние сервисы и платные базы.

==================================================
4. УМНЫЙ ПОИСК
==================================================

Не выполняй поиск по базе знаний для каждой простой реакции.

Простые реакции:

Спасибо
🔥
👍
Класс

по-прежнему:

- AI не вызывается;
- поиск памяти не выполняется;
- should_reply=False.

Для содержательного комментария:

1. Определить, является ли сообщение содержательным.
2. Сформировать текущий post context.
3. Выполнить поиск релевантных прошлых знаний.
4. Добавить найденные результаты в AI context.
5. Выполнить текущий AI-анализ.

==================================================

Расширь текущий контекст.

...

РОДИТЕЛЬСКИЙ КОММЕНТАРИЙ:

РЕЛЕВАНТНАЯ ИНФОРМАЦИЯ ИЗ ПРЕДЫДУЩИХ ПУБЛИКАЦИЙ:

[1]
Тема:
...

Содержание:
...

[2]
Тема:
...

Содержание:
...

КОММЕНТАРИЙ ПОЛЬЗОВАТЕЛЯ:
...

Не передавай слишком много информации.

Максимум:

- до 3 результатов;
- каждый результат ограничить безопасной длиной;
- общий memory context ограничить разумным размером.

Не изменяй max_tokens=8192.

==================================================
6. ЗАЩИТА ОТ НЕВЕРНОЙ ИНФОРМАЦИИ
==================================================

Добавь в AI system prompt правило:

Используй найденную память только как дополнительный контекст.

Не утверждай, что информация относится к текущему вопросу, если связь не очевидна.

Если в памяти нет достаточной информации:

- не выдумывай;
- отвечай только на основании текущего поста;
- при необходимости сформулируй нейтральный ответ.

Не позволяй памяти предыдущих публикаций подменять текущий контекст.

Текущий пост имеет более высокий приоритет.

9. ТЕСТЫ
==================================================

Добавь тесты минимум для:

1. Сохранение публикации.

Один и тот же post_message_id дважды.

Ожидается:

одна запись знания.

2. Поиск.

Сохранены публикации:

«Пожарный самолёт способен доставлять воду...»

«Пожарные используют специальные автомобили...»

Запрос:

«Сколько воды берёт самолёт?»

Ожидается:

первый пост релевантнее второго.

3. Текущий пост не должен дублироваться в memory context.

4. Нет совпадений.

Бот продолжает работать.

5. Простая реакция.

«🔥»

Ожидается:

поиск памяти не вызывается.

6. Содержательный вопрос.

«Чем этот самолёт отличается от предыдущего?»

Ожидается:

выполняется поиск памяти.

7. Защита от дублей комментариев.

Проверить, что новая память не нарушает:

один комментарий
→ максимум один AI-анализ
→ максимум один автоответ.

8. Ручные знания через /remember.

Проверить, что они участвуют в поиске.
