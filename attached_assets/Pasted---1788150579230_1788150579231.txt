Добавь контекст поста при автоматическом анализе и ответе на комментарии.

Цель:
Бот должен понимать не только текст комментария, но и контекст публикации, под которой этот комментарий был оставлен.

Например:

Пост про пожарный самолёт.

Комментарий:
«Сколько он поднимает?»

Бот должен понимать, что «он» — это самолёт из конкретного поста, а не задавать уточняющий вопрос без необходимости.

Важно:
Не ломай существующую архитектуру.

Сохрани без изменений:

- очередь комментариев;
- 2 worker;
- защиту от дублей;
- идемпотентность;
- уникальность (chat_id, telegram_message_id);
- обработку коротких реакций;
- OpenRouter;
- текущую модель;
- max_tokens=8192;
- Smart Auto;
- moderation;
- healthcheck;
- workflow.

Перед изменениями сначала изучи текущую архитектуру обработки комментариев, модели базы данных, repositories, Telegram handlers и AI service.

==================================================
1. ПОЛУЧЕНИЕ КОНТЕКСТА ПОСТА
==================================================

При получении комментария определить сообщение/пост, к которому он относится.

Используй существующие данные Telegram update и reply/comment relationship.

Для каждого комментария попытайся получить:

- chat_id;
- telegram_message_id комментария;
- идентификатор исходного поста;
- текст исходного поста;
- caption исходного поста, если есть;
- тип контента поста;
- при необходимости краткое описание медиа.

Если комментарий является ответом на другой комментарий, учитывать также:

- текст родительского комментария;
- автора родительского комментария, если это доступно.

==================================================
2. СОЗДАЙ POST CONTEXT
==================================================

Добавь понятную структуру или функцию для формирования контекста.

Например логически:

post_context = {
    "post_id": ...,
    "post_text": ...,
    "caption": ...,
    "parent_comment": ...
}

Не обязательно использовать именно такой формат.

Главное — чтобы AI получал структурированный и ограниченный по размеру контекст.

==================================================
3. ПЕРЕДАЧА КОНТЕКСТА В AI
==================================================

При AI-анализе комментария передавать:

КОНТЕКСТ ПУБЛИКАЦИИ:
<текст или caption поста>

КОНТЕКСТ РОДИТЕЛЬСКОГО КОММЕНТАРИЯ:
<если комментарий является reply>

КОММЕНТАРИЙ ПОЛЬЗОВАТЕЛЯ:
<текст комментария>

AI должен понимать связь между этими частями.

Пример:

Пост:
«Сегодня рассказываем о пожарном самолёте Ил-76...»

Комментарий:
«Сколько он поднимает?»

AI должен интерпретировать вопрос как вопрос о самолёте из публикации.

==================================================
4. ОГРАНИЧЕНИЕ РАЗМЕРА КОНТЕКСТА
==================================================

Не отправляй в OpenRouter бесконечный текст.

Сделай безопасное ограничение размера:

- ограничить текст поста разумной длиной;
- ограничить parent comment;
- не дублировать одинаковый контекст;
- не увеличивать max_tokens=8192;
- не менять OpenRouter настройки.

Если пост слишком длинный, использовать начало и/или наиболее релевантную часть.

==================================================
5. СОХРАНЕНИЕ КОНТЕКСТА
==================================================

Если текущая база данных уже хранит связь комментария с постом — используй её.

Если нет, добавь минимально необходимые поля.

Желательно сохранять:

- telegram_post_id;
- post_text или краткий контекст поста.

Не создавай сложную новую архитектуру без необходимости.

==================================================
6. ПОВЕДЕНИЕ ПРИ ОТСУТСТВИИ КОНТЕКСТА
==================================================

Если Telegram не предоставил текст исходного поста:

- бот продолжает работать;
- AI получает только доступный контекст;
- комментарий не должен падать с ошибкой.

Логировать примерно:

Post context unavailable, processing comment without post context

==================================================
7. SMART AUTO
==================================================

Сохрани текущую логику Smart Auto.

Но AI confidence и should_reply теперь должны определяться с учётом контекста поста.

То есть вопрос:

«А сколько он весит?»

без контекста может быть неоднозначным.

Но при наличии поста про самолёт — это нормальный содержательный вопрос.

==================================================
8. ПРОСТЫЕ РЕАКЦИИ
==================================================

Не ломай текущую оптимизацию.

Примеры:

«Спасибо»
«🔥»
«👍»
«Класс»

По-прежнему:

- AI не вызывается;
- контекст поста не требуется;
- PRAISE;
- should_reply=False.

Но:

«🔥 А сколько он поднимает?»

должен:

- распознаваться как вопрос;
- получать контекст поста;
- отправляться в AI.

==================================================
9. ТЕСТЫ
==================================================

Добавь тесты минимум для следующих случаев:

1.

Post:
«Пожарный самолёт способен доставлять воду в район пожара»

Comment:
«Сколько он поднимает?»

Проверить, что AI получает контекст поста.

2.

Post:
«Сегодня рассказываем о подготовке пожарных»

Comment:
«Как долго они этому учатся?»

Проверить связь «они» с пожарными.

3.

Comment без доступного контекста поста.

Проверить, что обработка не падает.

4.

Простая реакция:

«🔥»

Проверить:

- AI не вызывается;
- контекст поста не обязателен.

5.

Реакция + вопрос:

«Класс! А сколько он весит?»

Проверить:

- определяется как QUESTION;
- контекст поста передаётся в AI.

6.

Комментарий является reply на другой комментарий.

Проверить, что при доступности parent comment он передаётся в AI.

7.

Повторная доставка одного комментария.

Проверить, что защита от дублей продолжает работать при наличии post context.

==================================================

==================================================

Обязательно выполнить:

python -m compileall -q app tests

python -m pytest -q

Если тесты проходят:

перезапусти только:

Start application

После запуска проверить:

- Start application running;

- Comment processing queue started;
- GET http://127.0.0.1:8080/health возвращает HTTP 200.

Не меняй Secrets, API keys, OpenRouter provider, модель, max_tokens=8192, workflow или нерелевантные части проекта без необходимости.
